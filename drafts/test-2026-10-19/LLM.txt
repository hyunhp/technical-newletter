📰 LLM Research Weekly Papers | 4th Week of October 2026
Top Papers in Large Language Models (12 October - 18 October)

Researchers tested six mainstream agent memory systems on requests to delete something. None of them fully handled more than 1.5% of those requests. A second benchmark found that after the obvious memory was deleted, 39-76% of secrets could still be recovered from what was left.

🔎 What happened
Two teams built benchmarks for a test nobody was running: does an agent's memory actually forget when a user asks? Bemula has 50 multi-session dialogues with 135 forget requests of six types and 1,742 test questions. Each dialogue also has a control version without the requests, so a system only gets credit for forgetting something it really stored. The authors tested six mainstream memory systems on three backbone LLMs. None passed more than 1.5% of forget requests end to end, and most passed none. Systems either left the information extractable with simple attacks or deleted far more than asked. MemCut tracks the trail a secret leaves. It has 456 hand-designed secrets with annotated evidence, including messages that never state the secret directly. Even its LLM-guided deletion baseline left 39-76% residual recovery.

🛠 Why it matters
If you ship an agent with persistent memory, a "forget that" feature is a promise to your users. These results show the obvious implementation, which finds the matching memory and deletes it, fails in two ways. It misses indirect clues, or it wipes unrelated memories along with the target. MemCut's sweeps point to a practical fix. With a fixed deletion budget, searching a wider pool of candidate memories cut residual recovery more than deleting every original candidate did. So better retrieval coverage pays off more than more aggressive deletion. Test forgetting as its own feature, including extraction attempts.

🌱 In plain words
Say you ask an assistant to shred a letter about your doctor's appointment. They shred it. But your calendar still says "clinic, 3pm." A sticky note mentions the prescription. A draft reply sits in another folder. Anyone flipping through can rebuild the secret. That's what these benchmarks measure. Agent memory spreads facts across summaries and side remarks. Delete only the obvious entry and the trail stays. Delete everything nearby and you lose things you wanted to keep.

⚠️ Reality check
Both benchmarks are small and hand-built (50 dialogues in one, 456 secrets in the other). MemCut's 39-76% figure measures residual recovery, where a reader is handed the surviving memories directly. That test is stricter than what the system's own retrieval surfaces, and native recovery fell much more. Neither abstract shows how real users phrase deletion requests.

💭 Editor's Take
Agent memory is designed to write and retrieve, and deletion gets added later as a search. That's why it fails. Until a vendor reports something like Bemula's end-to-end pass rate, I'd treat "delete" claims in memory products as unverified. Watch for a system that records provenance when it writes, linking every derived summary back to its source turns, and reports both removal and preservation scores. If that pushes well past the 1.5% ceiling, this is an engineering gap and not a fundamental limit.

**(1) Can Agents Forget When Asked? A Benchmark for Memory Unlearning in LLM Agents** – Introduces Bemula, the first benchmark built for memory unlearning, and finds that no tested memory system completes more than 1.5% of forget requests end to end.

Read More : https://arxiv.org/abs/2610.18052

**(2) MemCut: Every Secret Leaves a Trail in the Long-Term Memory of LLM Agents** – Introduces MemCut, which follows each secret's evidence trail and shows that LLM-guided deletion still leaves 39-76% residual recovery, with candidate coverage as the bottleneck.

Read More : https://arxiv.org/abs/2610.21405

**(3) Do Factuality Methods Make LLMs More Factual? Reproducibility and Fair Comparison** – A reproducibility study that compares published factuality-alignment methods fairly to check whether they actually make LLMs more factual.

Read More : https://arxiv.org/abs/2610.18415

**(4) The Window Is in the Reasoning: When LLM Agents Decide to Follow Prompt Injections** – Uses branching rollouts to test whether an agent's decision to follow a prompt injection is settled when it reads the injection, an assumption that runtime monitors and single-run benchmarks share.

Read More : https://arxiv.org/abs/2610.24048

**(5) Enforcing Code Reasoning in Agentic Scaffold for More Effective Issue Resolution** – Across 7,955 SWE-bench issue-resolution trajectories from six scaffolds, finds 12 forms of code reasoning in 66.95% of trajectories and studies forcing that reasoning inside the agent scaffold.

Read More : https://arxiv.org/abs/2610.23782
