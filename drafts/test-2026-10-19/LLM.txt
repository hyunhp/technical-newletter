📰 LLM Research Weekly Papers | 4th Week of October 2026
Top Papers in Large Language Models (12 October - 18 October)

Researchers sent 135 forget requests to six mainstream agent memory systems. No system fully passed more than 1.5% of them, and most passed none.

🔎 What happened
Three new benchmarks tested what long-term agent memory does besides recall. Bemula pairs each of 50 multi-session dialogues with a control version, so a system only gets credit for forgetting something it actually stored. Across six memory systems and three backbone LLMs, the requested facts either stayed extractable under simple attacks, or the system deleted far more than it was asked to. MemCut follows 456 secrets through evidence trails, including messages that never state the secret outright. Removing the original disclosure cut recovery through normal retrieval much more than it cut recovery from the leftover stored objects. Even LLM-guided deletion left 39-76% residual recovery. MemBubble, built on preferences from real conversations, found that memory lowers response entropy by 34.7% on average compared with giving the model the full interaction history. Simple user-side fixes did not close that gap.

🛠 Why it matters
If you ship a memory feature with a "forget this" button, assume the button deletes the obvious record and nothing else. MemCut shows that a secret can be pieced back together from nearby turns that hint at it. Your privacy promises, data-deletion workflows and compliance answers should describe what deletion really does. Bemula shows over-deletion is the other way it fails, so a heavier delete is not a free fix. Separately, if your product suggests options or information, memory can quietly narrow what users get offered. Measure diversity before and after you turn memory on.

🌱 In plain words
Picture an assistant who takes notes on sticky pads. You ask them to forget your home address. They throw away the note that says "address", but other notes still read "lives near the blue bakery" and "walks 5 minutes to the station". Anyone reading the pile can still work it out. And because the notes keep saying "likes Italian", every dinner suggestion turns into pasta. That is what these benchmarks found: deletion leaves a trail, and memory narrows the choices you're offered.

⚠️ Reality check
These are research benchmarks with hand-designed secrets and set attack methods, and the abstracts do not name which commercial memory products were tested or how they perform in live use. Lower entropy is one way to measure diversity, and it doesn't directly tell you whether users ended up worse informed.

💭 Editor's Take
The bigger problem is architectural, not a quality gap. Today's memory systems pull facts out of conversations and spread them across many stored objects, and none of them tracks where each fact came from, so "delete" has nothing exact to point at. I'll believe a memory system can forget when one passes Bemula's extraction-attack suite while still keeping unrelated memories intact. Until then, treat memory opt-in as permanent disclosure and tell users that plainly.

**(1) Can Agents Forget When Asked? A Benchmark for Memory Unlearning in LLM Agents** – Lead: the first benchmark built for memory unlearning, finding that no tested system passes more than 1.5% of forget requests from start to finish.

Read More : https://arxiv.org/abs/2610.18052

**(2) MemCut: Every Secret Leaves a Trail in the Long-Term Memory of LLM Agents** – Shows why deletion fails: secrets can be rebuilt from leftover evidence, with 39-76% residual recovery even after LLM-guided deletion.

Read More : https://arxiv.org/abs/2610.21405

**(3) MemBubble: Benchmarking How Agent Memory Shapes LLM Response Diversity** – Adds a second cost of memory: responses lose 34.7% entropy on average compared with using the full history, and simple user-side fixes don't help.

Read More : https://arxiv.org/abs/2610.25127

**(4) Understanding KV Residency in Production-Scale Agentic LLM Workloads** – Looks at four production Microsoft M365 agent workload traces to see how much GPU memory it takes to keep agent context's KV state around for reuse.

Read More : https://arxiv.org/abs/2610.22863

**(5) The Window Is in the Reasoning: When LLM Agents Decide to Follow Prompt Injections** – Uses branching rollouts to test whether an agent decides to follow a prompt injection at the moment it reads it, an assumption that runtime monitors and single-run benchmarks both rely on.

Read More : https://arxiv.org/abs/2610.24048

**(6) How Effectively Do Security Skills Guide Coding Agents in Vulnerability Detection in Linux Kernel?** – A large-scale study of 37 security skills used with Claude Code to find real Linux kernel vulnerabilities, including why the agent fails.

Read More : https://arxiv.org/abs/2610.25705
